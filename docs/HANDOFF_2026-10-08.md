## 4. Measurements and rejections worth remembering (numbers in `docs/PERFORMANCE_FINDINGS.md`)

- Section 9 test list: kept IPC head-offset parsing and 4096-byte recv buffers; rejected bar timer alignment, an "unchanged" flag, `-march=native`/no-LTO, mmap, read coalescing.
- Section 12 correction: the earlier hover tests never reached the bar (no pointer capability); re-run gives the same conclusion (bar +1-3 ms per 20 s of sweep, compositor 0.9% of a core at 130 events/s; live tooltips +9 ms compositor per 20 s while shown).
- Section 13/14: a perfect prewarm saves 3.5 ms of a bar start on the VM; in-process replay is worse; parent asking early + file heads recovers 1.4 ms; end to end compositor-to-bar-buffer 354 vs 355 ms (noise 25 ms).
- wpctl fallback vs native PipeWire in the bar: no measurable difference (8 runs). Lock applet retries its IPC connect about every 1.5 s only while the compositor is gone.

## 6. Incidents and traps from this session

- **Blank screen on the VM (unresolved)**: my cleanup `pkill -x` killed the live session's bar and wallpaper (and once the live compositor, which the greeter restarted). My attempt to relaunch them in the live session was refused by the permission classifier. The owner must log out/in on the VM or run `fleetwm-wallpaper &` and `fleetwm-bar &` there with `XDG_RUNTIME_DIR=/run/user/1000 WAYLAND_DISPLAY=wayland-0`. Ask before touching the live session.
- `git add -A` swept staged multi-monitor work into an unrelated commit once (fixed with `reset --soft` and path-wise commits): stage by path.
- A `wl_output` v4 listener must fill the `description` slot or the client aborts ("listener function for opcode 5 of wl_output is NULL").
- wlroots scene rect colours are premultiplied. The pointer helper `ptr` needs `PGO_W/PGO_H` for any size other than 1280x720.
- `pgrep -x` takes the 15-character comm name (`fleetwm-wallpap`); a bare `wait` in a script hangs on setsid'd children; `bc` and `rsync` are not on the VM.
- `WAYLAND_DEBUG` timestamps and Python's monotonic clock have a constant offset on the VM: only differences between runs mean something.
- A new window opens clamped to the work area top because the cascade offset is -112 px for the first window (by design).
- Permission classifier: remote shell writes into the live session and writes outside the session scope are blocked; test rigs under `/tmp` and `~/perf-test` are fine.
