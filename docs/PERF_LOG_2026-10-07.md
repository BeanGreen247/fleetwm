## 02. membench on the Celeron, schedutil  (2026-10-07 19:46)
- Machine: laptop, Celeron N4020, governor `schedutil` (intel_cpufreq passive), live fleetwm session idle beside it; CPU at 2.69-2.78 GHz after each run (turbo range up to 2.8 GHz).
- Step: `perflog/2026-10-07/membench_sse.c` is `lestrix/native/bench/membench.c` ported: AVX2 intrinsics replaced by SSE2 (the N4020 has no AVX), thread pinning `i % nprocs` (the original pins CPUs 0,2,4,6), thread counts 1/2/4 (4 = oversubscribed on 2 cores). Built on the laptop `gcc -O2 -pthread`, three consecutive runs, `scp` to /tmp, no sudo.
- Result (GB/s, memcpy counts read+write traffic; best of 3, the three runs agree within ~3% except where noted). "L3" row = 2 MB per thread: the N4020 has no L3, this is the shared 4 MiB L2, so 1 thread fits, 2 threads just fit, 4 threads spill.

| Test | 1 thread | 2 threads | 4 (oversub.) |
|---|---|---|---|
| memcpy L1 (16 KB) | 40.6 | 60.7 | 60.7 |
| memcpy L2 (128 KB) | 30.5 | 40.5 | 40.5 |
| memcpy 2 MB (shared L2) | 16.8 | 19.1-20.1 | 18.8-19.4 |
| memcpy RAM (64 MB) | 11.4-11.6 | 14.2-14.4 | 14.2-14.5 |
| RAM read (SSE2 sum) | 7.1 | 10.3-10.4 | 10.1-10.4 |
| RAM write (memset) | 9.3-9.4 | 10.4-10.5 | 10.6 |
| NT stream write, any size | 9.5-10.4 | 10.5-10.6 | 10.5-10.6 |

- Compared with the i5-8265U in PERFORMANCE_FINDINGS.md section 3: RAM copy traffic 14.4 vs 25 GB/s (1 thread 11.5 vs 25.7), single-thread RAM read 7.1 vs 14-19 GB/s, RAM write ceiling 10.6 vs 27-29 GB/s. The ceiling for any one write stream is ~10.6 GB/s and two threads already saturate it (single-channel memory). Run-to-run noise is under 3%.
- Speed-of-light consequence: 1080p x 4 bytes = 8.3 MB per full frame. A full-frame shm upload (read 8.3 MB, write 8.3 MB through one copy) costs about 8.3 / (11.5/2) = 1.4 ms of pure memcpy at the 1-thread RAM figure; at 60 fps that is 8.6% of one core and about 1 GB/s of the 14 GB/s copy ceiling. The 1.1 ms CPU per frame measured earlier for the whole compositor on a scrolling terminal (about a third in `rep movsb`, ~0.4 ms) is therefore well under the copy limit: that copy is not bandwidth-bound for damaged areas, it is the unavoidable upload.
- Decision: keep as the reference table for later estimates. Next: governor comparison needs `sudo` on the laptop (writes to scaling_governor): asking the owner first.
- Raw: perflog/2026-10-07/02-membench-schedutil.txt
